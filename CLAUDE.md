# CLAUDE.md — правила проєкту «Закулисье / Backrooms»

## Як ми працюємо

- Власник проєкту керує розробкою **словами**, код не пише й не читає. Claude — і розробник, і тестувальник: сам пише код, сам перевіряє в браузерах, сам дивиться скріншоти і сам виправляє.
- Спілкування з власником — **українською**, просто, без технічного жаргону. Пояснювати, що змінилося *в грі* (що побачить гравець), а не в коді.
- Мета — гра, яка **виглядає й відчувається професійно** в Chrome і Safari, на комп'ютері й телефоні.
- Перед великими або спірними змінами (геймплей, баланс, стиль, видалення контенту) — коротко запитати. Дрібні виправлення та очевидні баги — робити одразу.
- Кожну видиму зміну підтверджувати скріншотом і показувати власнику (SendUserFile або Read скріншота перед описом).

## Цикл роботи над задачею

1. Зрозуміти задачу, знайти код (`src/…`).
2. Змінити код.
3. `npm run lint` — без помилок.
4. Подивитися результат скріншотами (`npm run shot -- …`), мінімум Chromium **і** WebKit; для інтерфейсу — ще й телефон (`--device "iPhone 15 Pro landscape" --browser webkit`).
5. Для значних змін — `npm run check` (lint + build + smoke в обох браузерах, ~4 хв).
6. Коміт у `main` з пояснювальним повідомленням англійською, `git push`. GitHub Actions перевіряє й публікує сайт автоматично.
7. Коротко звітувати власнику: що змінено, скріншот, посилання на сайт.

### Скріншоти (`scripts/shot.mjs`)

```
npm run shot -- --level 3                          # рівень 3, точка старту, Chromium
npm run shot -- --level all --browser all          # усі рівні в Chromium і WebKit
npm run shot -- --level 0 --scene exit             # перед дверима виходу
npm run shot -- --level 5 --scene monster          # монстр перед камерою
npm run shot -- --panel settings --lang uk         # екран меню
npm run shot -- --device "iPhone 15 Pro landscape" --browser webkit --level 2
npm run shot -- --level 4 --eval "__zk.look(1.57)" # довільний JS перед знімком
```
Файли — у `.shots/` (в git не потрапляють). Кожен знімок друкує JSON: помилки сторінки, `info()` гри, FPS (`--fps`).

**FPS у контейнері не показовий**: немає GPU, рендер програмний (SwiftShader). Порівнювати лише відносно (до/після зміни), а реальну продуктивність оцінювати за кількістю draw calls/трикутників і складністю шейдерів.

### Профілі графіки (`src/core/device.js` + `PROFILES` у `game.js`)
- При запуску визначаються платформа (`apple` — iPhone/iPad/Mac, `android`, `other`), форм-фактор і рівень GPU 0–3 (detect-gpu; запасний варіант — за назвою GPU). Програмний рендер (SwiftShader, CI, контейнер) — рівень 0 → «Низька».
- «Авто» = `autoProfile()`: Apple 3→`ultra`, 2→`high`, 1→`med`; Android 3→`droidHigh`, 2→`droid`, 1→`droidLow`; інші ≥2→`high`. `ultra` — рідна роздільність до 3×, MSAA 4×, анізотропія 16×. Android: ≤ 60 кадрів (екрани 90/120 Гц), без MSAA, 1K-текстури, свічення в ¼.
- **Рішення власника: нічого не урізати заради швидкості** (роздільність, кадри, звуки, радар, ефекти). Оптимізувати лише так, щоб гра виглядала й звучала так само (прибирати зайву роботу, готувати заздалегідь, переносити з головного потоку). Роздільність — рідна (до 2× на «Високій», до 3× на «Ультра»); обмеження 60 кадрів — лише на Android (просив власник). Тіні N8AO: `ao` у профілі (0/½/повна), вбудований код у `src/render/n8ao` (CC0).
- Живі лампи вимикаються через `visible` (світло випадає з шейдера), а не нульовою яскравістю.
- Перевірка профілів: `npm run shot -- --q auto --device "iPhone 15 Pro landscape" --query "tier=3"` (`--query` також `apple`/`android`). У налаштуваннях гравець бачить рядок «Пристрій: …, «Авто» = …».

- **Довідкові репозиторії** (не залежності гри, ~2 ГБ): `bash scripts/fetch-refs.sh` клонує в `../refs/` вихідний код і приклади. Контейнер одноразовий — на початку сесії запускати скрипт, якщо `../refs` немає. Перш ніж писати ефект/систему — подивитися, як це зроблено там.
  - Графіка: `three.js` (приклади + довідка саме r160), `postprocessing`, `n8ao` (AO), `three-good-godrays` (промені світла), `three-gpu-pathtracer` (еталонний фото-рендер для налаштування запеченого світла), `troika` (чіткий 3D-текст), `lygia` (шейдери — **лише читати**, ліцензія Prosperity, код не копіювати).
  - Продуктивність/телефони: `detect-gpu` (пресет якості за GPU), `glTF-Transform`, `meshoptimizer`, `basis_universal` + `KTX-Software` (стискання текстур у KTX2), `Spector.js` (аналіз кадру: draw calls, шейдери).
  - Монстр: `yuka` (ШІ: сприйняття, стани, рух), `recast-navigation-js` (навмеш, пошук шляху), `three-mesh-bvh` (колізії/raycast).
  - Звук і керування: `Tone.js` (синтез, ефекти), `standardized-audio-context` (особливості WebAudio в Safari), `howler.js`, `nipplejs`.
  - Інше: `modern-web-guidance` (поради Chrome для меню/UI), `WaveFunctionCollapse` (ідеї генерації рівнів, C#).
  - Сумісність із three 0.160: `postprocessing` лише **6.35–6.36.x** (новіші вимагають three ≥ 0.168); `n8ao` 2.x і `three-good-godrays` працюють поверх нього (підбирати версію під postprocessing 6.36); `three-mesh-bvh` 0.9.x (three ≥ 0.159); `troika-three-text`, `recast-navigation` — будь-яка three; `three-gpu-pathtracer` новий потребує three ≥ 0.187 — лише як окремий інструмент, не в грі. Відкинуті: `realism-effects` (покинутий з 2024, важкий), `resonance-audio` (архів), `rapier.js` (переїхав; колізії вистачає своїх + BVH).
- Перед встановленням бібліотеки — коротко пояснити власнику, навіщо вона потрібна. Встановлювати через npm лише ту, що потрібна зараз.
- Гра має добре працювати в **Safari на iPad та iPhone**.
- На iPhone/iPad **звук вмикається після першого дотику** до екрана (AudioContext створюється/відновлюється в обробнику жесту).
- Після змін — запускати проєкт і перевіряти, що все працює без помилок (`npm run check`, скріншоти `npm run shot`).

## Правила

- **Мова гри**: вихідна — російська (`src/i18n/locales/ru.js`), є `uk` і `en`. Новий текст інтерфейсу — **одразу** через `t()`/`data-i18n` з перекладом у всі три словники. Старі рядки в JS переносити поступово; поки не перенесені всі, `I18N_READY = false` (перемикач мови схований).
- **Сейви**: ключ `localStorage` `zakulisye_v2`, id записок і досягнень не змінювати — інакше гравці втратять прогрес.
- **Секретні коди** в «Об игре» (`data-w="a|s|p|i"`) — частина геймплею, атрибути не чіпати.
- **Safari**: перевіряти WebKit на кожну зміну рендеру, звуку, керування чи CSS. Пам'ятати: AudioContext стартує лише після жесту; pointer lock на iOS немає; `100vh` на iOS — використовувати `dvh`/safe-area.
- **Продуктивність**: ціль — стабільні 60 FPS на середньому телефоні. Не додавати динамічних джерел світла й тіней без потреби; світло в рівнях «запечене».
- **Онлайн**: PeerJS (публічний сервер + TURN). Не ламати протокол без підвищення `PREFIX` у `net.js`.
- Коміти — англійською, атомарні, з поясненням «чому».
- Не комітити `.shots/`, `dist/`, `node_modules/`.

## Сервер гри (`server/`, хостинг Ample — акаунт власника)

- Один файл `server/server.mjs` (Node 22, `pg`, `web-push`), керована Postgres від Ample. Адреса — `src/net/config.js` (`SERVER`). Розгортання: workspace Ample → `ample_deploy` (змінні `ADMIN_KEY`, `VAPID_PUBLIC`, `VAPID_PRIVATE` зберігаються в Ample; **у git не класти**; якщо ключа адміна немає — згенерувати новий і передеплоїти з `env`).
- Що вміє: `/auth/register|login|logout` (ім'я 3–20 + пароль ≥6, scrypt), `/save` GET/PUT (хмарна копія `SAVE`; клієнт `src/net/account.js` об'єднує без втрат: списки — об'єднання, рівні — максимум, налаштування — з пристрою), `/perf` і `/bugs` (звіти гравців, `src/net/reports.js`), `/push/subscribe|unsubscribe`, `/admin/reports` і `/admin/delete` (заголовок `x-admin-key`).
- Автотести (Playwright → `navigator.webdriver`) і dev-сервер **не** шлють звіти на справжній сервер (`LIVE_REPORTS`), хіба `?reports`.
- **Сповіщення — лише великі релізи**: планова задача Ample `release-check` кожні 15 хв викликає `POST /tasks/release`; сервер читає `public/release.json` з `main` і розсилає push, тільки коли змінився `id`. Тому `id` у `release.json` міняти **лише після завершення всього плану робіт** (рішення власника), не при дрібних оновленнях. Сервіс-воркер `public/sw.js` лише показує сповіщення (не кешує). На iPhone/iPad push працює тільки з гри, доданої «На екран Додому».

## Ігровий дизайн (поточний напрям)

- **Відкритий світ**: кожен рівень — світ 81×81 клітинку (~160 м), 3×3 блоки-зони з різним плануванням (`layWorld` у `level.js`), один блок-пара — гігантський атріум. Мета рівня — знайти вихід: **3 виходи на світ** (головний у найдальшій точці + 2 в інших дальніх зонах, `G.exits` / `lvl.exits`), усі ведуть на наступний рівень; зелене сяйво над кожним, маячок і телефон — до найближчого (`nearestExit` у `game.js`). `npm run qa` перевіряє, що всі досяжні (`WORLD = true`, `levelTask`). Старі завдання (запобіжники, код…) збережені в коді, але вимкнені.
- Зони мають назви (`zone.*` у словниках) і показуються при вході.
- Геометрія світу розкладена по квадратах 12×12 клітинок (`CGB`) — для відсікання невидимого. Нові масові об'єкти теж ділити по квадратах.
- **Дивні знахідки** (`src/world/finds.js`): місячний модуль, космонавт, процесія з газетами (ходить атріумом), карусель, салон літака, автомат із газуванкою. 5 на світ; процесія завжди в атріумі. Місце розчищається в `genGrid`, моделі — з примітивів + canvas-текстур, матеріали через `shaded()` (об'ємне освітлення). Виявлення — у полі зору ближче 9 м: напис, +рассудок, журнал «Находки» (`SAVE.finds`). Високі моделі ужимаються під стелю (`height`).
- Перевірка знахідок: `npm run shot -- --level 0 --seed 1 --scene find:seats` (kind або номер).
- **Монстри** — готові скелетні моделі CC0 (Quaternius human/zombie, `public/assets/models`, конвертер `scripts/convert-models.mjs` FBX→GLB) з переробкою в `src/world/monster-models.js` (`RIG`: база, анімації, пропорції кісток, зріст); шкіра — `skinTexture`, деталі — `decorate()` у `entity.js`, кріпляться до кісток через «точки кріплення» в метрах. Якщо модель не завантажилась — процедурний монстр (`makeEntityMesh`).
- **Шафки** (`src/world/lockers.js`): 3 моделі — `school` (металеві в ряд 1–3), `wardrobe` (дерев'яна шафа з жалюзі), `cabinet` (промислова двостулкова з перфорацією); набір і палітра по темі (`THEME`), у межах рівня — колір/знос/розмір/прочинені дверцята. Дверцята на петлях з реальними щілинами; внутрішні поверхні темні (`doorMat`), тож зсередини світло видно лише крізь щілини. Текстури CC0 PaintedMetal012, Wood066.
- **Ховання чесне**: монстр «знає», що ти в шафці, лише якщо бачив вхід (`ent.seeMeT < 0.4` + LOS); забуває, коли здається або відходить > 25 м.
- **ШІ монстра** (`Entity.update`): конус зору ~140° (+бік зблизька), підозра `sus` копиться (швидше — близько, біг, ліхтарик; повільніше — присів, темрява), при 0.4 — йде перевіряти зі звуком (`hooks.notice`), при 1 — погоня; після втрати — обшук останнього місця і здається; детектор застрягання; патрулювання біля шафок.
- **Референси власника** (зберегти напрям): великі жовті зали з ковроліном і довгими лампами-смугами в стельових плитках; купа меблів як знахідка; монстр із ТВ-головою (Двойник); шкільний коридор із зеленим світлом над дверима; двір серед стін із вікнами; білий кахельний коридор зі світлом зі стелі й водою.

  - Вигляд: ширококутний «риб'ячий» об'єктив камери, густа сітка дрібних квадратних ламп, яскраві жовті зали з колонами, світлий серпанок, пил, монументальні знахідки (місячний модуль, лави з манекенами, планетарій, ковзанка, басейн, сходи «9»).
  - Пост-обробка своя (без EffectComposer): MSAA-кадр з глибиною → GTAO → bloom (поріг 1.4, коліно 0.6, 6 рівнів) → motion blur → fisheye → хром. аберація, віньєтка, зерно, **автоекспозиція** (adaptRate .03, key .24); toneMapping у рендерері вимкнено.
  - Текстури шпалер/килима/стелі — процедурні 1024², генеруються у **Web Worker**; кожне з ~150 «місць» — окремий lazy-чанк; світ будується шматками в `requestIdleCallback`; `compileAsync` («warming up the lights…») перед показом.
  - Мобільний пресет D9: pixelRatio 1, renderScale 0.7 (динамічно 0.35–0.85), msaa 0, AO off, far 95, LOD. Десктоп: pixelRatio 2, msaa 4. **Власник не дозволяє знижувати роздільність** — у нас лише безвтратні оптимізації.
  - Онлайн — Cloudflare Workers WebSocket-кімнати (шарди); аналітика PostHog з performance marks.
- **Escape the Backrooms** (Steam/PS5, 1–4 кооп): фотореалізм, мінімальний HUD, рівні з вікі Backrooms, сутності (Smilers, Skin-stealers), голосовий чат поблизу.
- Уже взято: лінза камери (L), сховати HUD (H), густі лампи + серпанок на рівні 0, колони в залах, безобличні манекени.

## Сюжет (рішення власника)

СРСР, 1986–1987: після вибуху на ЧАЕС у зруйнованому блоці знайшли «Шов» у реальності; під станцією — секретний Об'єкт 4-Б (офіційно — сховище відходів). Гравець — 7-ма експедиція з камерою (REC). Вступ — `PROLOGUE`; по документу на рівень — `DOCS` (журнал «Документи», `SAVE.docs`); записки — люди попередніх експедицій; фінал з вибором `ENDINGS.leave|stay` (`src/data/game-data.js`). Завдання рівнів (`TASK_BY_LEVEL` у `extras.js`) прив'язані до сюжету; у відкритому світі предмети завдань — 16–70 м від старту.

## Звуки

Записи CC0 (Meta Open Sound) у `public/assets/sfx/*.mp3` вантажаться після першого жесту (`sound.loadSamples`), синтез — запасний варіант. Фон страху (`startDread`) залежить від близькості монстра; далекі випадкові події — `ambientEvent`.

## Відомі проблеми (беклог)

- Кооп: погляд будь-якого гравця заморожує монстра для всіх (задумано як «будь-хто дивиться — він стоїть»; переглянути, якщо власник скаже).
- Голос недоступний у режимі `room` (всередині Claude), хоча довідка обіцяє мікрофон.
- Ігрові рядки в JS ще не перенесені в i18n.
- `game.js` ~1800 рядків — розбити на модулі (player, hud, menu, input, coop).
